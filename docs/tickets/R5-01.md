# R5-01: P0 / H runtime + integration: queued-session startup (org limit 3), deterministic pre-payment checkpoints with force_answer (P11), gateway-city verification + fragment-preserving start URLs (P12), redirect diagnostics, Njuko scrub fixes, R5 docs/queue/owner feedback, final 3-agent live acceptance

## Specification

Root causes verified by the planner (2026-11-09): (i) the H org quota is limit=3 concurrent sessions (GET /api/v2/sessions/quota -> {scope:org,limit:3}); above it H returns 201 status `queued`, but hclient starts its 45 s 'no reviewed page yet' deadline at create time, so queued sessions are killed as provider_error 'Browser startup unavailable' (R4 P0-5, and any P7 alternative/retry while 3 sessions run). (ii) Every started H run ends step_limit: hclient raises _StepLimit at metrics.steps>=max_steps without ever asking the agent to answer, even when the observed URL is already the safe pre-payment page (IHG select-enhance-stay / pay, Njuko currentPage=form_individual-form). H exposes POST /sessions/{id}/force_answer (agent answers from its current context on the next step; docs hub.hcompany.ai/agents-api/sessions/force-answer.md) and POST /sessions/{id}/messages. (iii) unreviewed_redirect keeps no diagnostic, so Vueling's redirect target is unknown. (iv) gateway transport (Den Haag via Amsterdam) cannot verify because city matching is a substring of expected.city; hclient strips URL fragments (NS International #/ routes). (v) scrub_url rejects real Njuko URLs with phone-like numeric or hex /w/<id> segments (Geneva, Den Haag widget). IMPLEMENT in hclient.py: 1) Queue-aware startup: read session status from create/changes; while status is `queued` or `pending` do not run the 45 s/3-blank deadline; emit one friendly step_progress 'En attente d'un navigateur disponible' (honest, no counts); start the 45 s deadline and the per-agent 10-minute budget when status becomes `running`; cap total queue wait at 8 minutes then blocked provider_error. Send an Idempotency-Key header on create (and on the pre-progress retry use a new key). Never print keys. 2) P11 checkpoints (new pinned interface, document in CONTRACTS.md): a task (and each P7 alternative) may carry `checkpoint: {url_patterns: [regex], beyond_patterns: [regex]}` (patterns matched case-insensitively against unquoted path+'?'+query of the reviewed observed URL; invalid regex/types -> ignore checkpoint, fail closed for READY). When a reviewed observation matches url_patterns: emit its frame, POST /sessions/{id}/force_answer once, keep polling up to 60 s for the answer, then evaluate with the existing _verified (handoff must equal the checkpoint URL). When an observation matches beyond_patterns (guest/passenger details, /pay, payment) it is a hard boundary: cancel the session immediately and return blocked with reason_code `policy_denied` (or `unsafe_claim` if the agent's answer claims a booking/payment), handoff = last observed reviewed checkpoint URL if any, else the existing fallback rules; never READY. Step budget: at steps >= max_steps-3 (and on H error_code step_limit if the session still accepts commands) call force_answer once and wait <=45 s before raising _StepLimit; a verified answer can still be READY only if the final observed URL matches the task checkpoint (when present). Include `checkpoint` patterns in the prompt only as 'stop page' hints, never raw regex to the UI. Tasks without checkpoint keep current behaviour. 3) P12 (document in CONTRACTS.md): `expected.gateway_city` optional string for hotel/transport; when present, verification `city` may match either expected.city or gateway_city (exact normalized equality or substring as today), never any other city. Task key `keep_fragment: true` keeps the start_url fragment if scrub_url(start_url) is unchanged and the policy review of the fragment-less URL is allowed; otherwise strip as now. 4) Redirect diagnostics: on unreviewed_redirect record the scrubbed host+path (no query/fragment) of the offending URL in a new optional StepResult field `blocked_url_host` (models.py, additive, validated public host/path only, never shown raw in the UI copy) and in step logs; non-http(s) browser-internal URLs (about:*, chrome:*, chrome-error:*, data:, blob:, empty) are treated like about:blank (skipped, same limits), never as redirects. 5) scrub.py: accept Njuko-style path segments (`/<slug>-2027-<13 digit id>`, `/w/<hex id>`) while still redacting phone numbers in query values/text, emails, tokens; add regression tests with the real Geneva/Den Haag shapes and with true phone/email cases. 6) Frames: keep only genuine observation images; additionally emit friendly step_progress 'Étape N' (from metrics.steps, monotonic) so the UI can show honest activity between frames. 7) Core: providers.LiveRunner/app keep launching 3 kinds concurrently (no serialization); mission result for queued-then-running agents unchanged. 8) Docs (this ticket alone owns shared docs): R5 queue in docs/tickets/index.json + docs/tickets/R5-0x.md (copy each R5 ticket spec + exact Allowed files), replace tests/test_r4_scope_contract.py by tests/test_r5_scope_contract.py (same checks for R5-01..R5-05, CONTRACTS markers P11/checkpoint/force_answer/P12/gateway_city), update AGENTS.md/PLAN.md/README.md/HANDOFF.md to the R5 queue (no stale Milan-only/frozen journey wording anywhere; after launch keep 3 agent cards and below ONLY the agents acting live, never raw task/prompt/JSON/logs; immediate streaming/typing feedback; 'fully functional, beautiful, near-perfect site by morning'), the Strava design priority, the exact live-success definition, the adversarial requirement and the site-policy rules (Accor denied). 9) PR-A merges as soon as green.
