## Spec
Remove automatic public trajectory publication entirely: no POST /sessions/{id}/share in the normal live path and no public/private H session/share/resource URLs emitted to consumers. Continue real screenshot bytes from the authenticated documented events/resources API, with bearer only on the exact own-session provider resource path, validated public HTTPS redirects, MIME/size checks and no credential leakage. A failed share endpoint must be irrelevant because sharing is never attempted. Keep latest genuine screenshot/progress events flowing until terminal events have been drained, including HTTP 204 after terminal state.

Before creating any H session, lazily call the pinned site_policy.evaluate_url(start_url, kind), checking each planned allowed navigation domain against the reviewed purpose/scope. Missing registry/module, unknown/expired/denied policy, forbidden Accor or missing screenshot scope produces a short blocked result and ZERO provider create calls; never fail open. Tell the hosted agent to stay within the explicitly reviewed hosts/paths, and cancel on the first observed unauthorized destination/forbidden-state signal. Read official H docs before changing requests; use a documented pre-action/domain restriction if available, never guess API fields. Be explicit that prompt instructions/post-observation cancellation are not an enforceable per-action firewall; if a requested flow cannot be done safely, block instead of claiming safety.

Honor task budgets of 80 up to a bounded hard cap of 120 (or the documented provider maximum if lower), retain a bounded wall-clock timeout and remote cancellation for timeout, client cancellation, unsafe claims, cap/HTTP/parse/callback failure. Do not add unlimited retries or rerun a forbidden action. Validate timeout/step semantics from official docs and expand mocked coverage for terminal drain, cap edges, resource redirects and cancellation failures.

Use the task expected object in the H prompt and structured answer schema. Require kind-specific extracted verification: correct race edition/date/distance at untouched participant-data boundary; selected hotel room/rate, stay/party/total; selected outbound+return/fare with correct arrival/return/party/total and next safe boundary. Compare returned dates/route/party with expected, validate safe public handoff URLs and actual observed page/frame context, reject explicit contradictions in URL dates, and never accept ready for missing/mismatching verification, a blocker, account wall, bare homepage, unselected results or unsafe action claims. Preserve existing public result keys/statuses and run(task,on_event) signature; internal verification details can be richer without requiring a core schema change. Self-reported model fields alone are not external proof: document that final human inspection of screenshot evidence is required.

Stop forwarding policy/message events, reasoning, tool names/arguments, task echoes or raw reached_step prose as user-visible logs. Emit curated short status messages and sanitized terminal summaries/errors only. Keep enough internal non-sensitive classification for honest blockers, not raw provider payloads. Strengthen scrub_text/scrub_url to remove artificial payment/card/contact/credential/token patterns including spaced/hyphenated numbers and URL values, while preserving ISO dates, ordinary budgets, race distances, event ids/slugs and legitimate date/route parameters. Preserve both sanitizer signatures so guide/core consumers work on baseline and updated main. No OCR-redaction guarantee: do not navigate authenticated/personal pages; suppress/cancel on suspected sensitive frames instead of storing them.

Tests must stub the policy lookup or mock module for standalone work before R2-02 lands; no sibling-file edits. Once reviewed policies are available, run a narrow real authorized smoke and verify screenshot bytes with zero public sharing, honest stop state and no raw task output; do not equate it with three-agent product success.
