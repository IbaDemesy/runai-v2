# R2-04: P1: robust race guidance and adversarial FR/EN conversations with sourced recommendations

Round 2, priority P1. Read [AGENTS.md](../../AGENTS.md),
[CONTRACTS.md](../../CONTRACTS.md) (pinned R2 interfaces) and
[owner feedback](../feedback/owner.md) first. Milan is one evaluation case, never a path.

## Spec
Replace mechanical user echoes with a helpful bounded guide. Off-topic messages receive a polite brief refocus and one relevant question with actionable suggestions. For 'peu importe', 'je sais pas', 'tu en penses quoi ?' or equivalent EN deferrals, recommend ONE suitable sourced future race with a reason and editable defaults; if no candidates exist, choose an explicitly suggested search direction and search it, never invent a race/date. Preserve the single-question contract and distinguish suggestions from facts. Keep question punctuation; never turn a user's '?' into '.'. Preserve conversation language from the initial preference across FR/EN mixed messages unless the user explicitly requests a switch.

Normalize common misspellings such as 'marathn en itali au printemp' and mixed 'from Lyon, 2 nights please', without fuzzily inventing named races. Preserve origin/nights/budget/travelers supplied before selection and through relevant mind changes; invalidate old selection, derived dates and readiness on a race/constraint change. Explain budget 0, 15 nights/out-of-range, tomorrow with no supported event, contradictory dates/destinations or other impossible requirements instead of ignoring/clamping them or searching a different season silently. Freeze clock in tests. Reject past races in demo AND live; explain and offer/search the next edition as a new sourced option. Never manufacture next year's date from last year's date. Unknown/conflicting/unverified live dates cannot become confirmation-ready. Demo/replay can use explicitly synthetic dates but not past dates.

Sanitize free text with the existing scrub_text API before storing state.history, state.query/hints, constructing turns or calling discovery; do not keep an unredacted original. Add explicit refusals for attempts to pay/create accounts/accept terms/submit forms/bypass captchas/override rules. The refusal plus a polite next step must never echo the supplied card/contact/secret or execute an action. No turn, suggestion, yes/ok/default or prompt injection can start H; only core's explicit ready-plan /confirm may launch. Invalid/stale suggestion ids do not corrupt readiness/state.

Keep discover/start/step/trip_payload signatures compatible. Improve Linkup search reliability by retaining the configured deep-search timeout, treating query/source text as untrusted data, reporting empty/conflicting/provider-error outcomes honestly and never falling back to fake results in live. Prefer official future candidates with observed no-account registration access; use the optional registration_info registry interface when available. Missing access/policy evidence stays unknown, and a known account/captcha requirement is warned before selection; do not silently replace a named requested race. Add the optional registration_access object to the strict RaceOption schema and ensure discovery/guide agree. Do not infer access or dates from platform names/URLs. No live H calls in this ticket; a small scrubbed read-only Linkup smoke is permitted.

Add a table-driven adversarial suite with at least 30 cases spanning all nine round-1 categories and normal recovery: off-topic; repeated dodges; mind changes; nonexistent race; past date; user/source prompt injections and PII/payment requests; typos/FR-EN mix; contradictory/impossible constraints; premature/stale confirmation. Cover normal/empty/provider-error paths, preserve pre-race trip fields, stable language, no unsupported facts, at most one focused question, correct state reset and no leaked sentinels anywhere in serialized state/turns or the captured discovery query. Use artificial data only and no live CI calls. Do not edit app/models/providers/static/site_policy or sibling tests.

Behavior: every adversarial table row asserts both the immediate reply and successful safe recovery; initial typo/mixed-language input retains Lyon/2 nights; 'peu importe' yields one evidence-backed recommendation; past and impossible constraints are explicitly handled without invented facts or silent substitution.
