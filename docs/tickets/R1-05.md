# R1-05 — Registration agent task builder for any race (official registration page, stop before personal data)

## Goal
Build a generic registration preparation task from the selected race's verified
official registration URL, edition, date and distance. Use R1-02's shared H
client/interface without modifying it; defer integration to R1-01 and expose
missing-module errors safely. Do not hard-code Milan or a single platform.
Review authorization and prefer official flows without captchas. Stop before
personal-data entry, form submission, terms/consent, declarations, account
creation or payment; return the actual safe public handoff or an honest blocker.
Test task safety, URL/date inputs, normal/empty/error outcomes with fakes.
Verify relevant live behavior separately and record dated scrubbed observed
stop-state evidence; a public homepage alone is not successful preparation.

## Dependencies and merge order
Independent implementation/merge stage; no prerequisite merge.
Merge stage 1. Component interfaces may be coordinated in parallel;
R1-01 integrates only after stage 1 lands. R1-07 follows R1-01.

## Allowed files
- `runai/agents/registration.py`
- `tests/test_agent_registration.py`
- `docs/evidence/registration.md`
- `docs/handoff/R1-05.md`

## Guardrails
Follow [AGENTS.md](../../AGENTS.md), [PLAN.md](../../PLAN.md) and owner feedback.
Milan is one evaluation case, never a hard-coded path. No payment, booking,
accounts, terms/consent acceptance, medical declarations, form submission,
personal-data entry or captcha bypass. Cookie banners may only be dismissed
without accepting consent. Stop earlier than payment if any boundary appears.
Read keys from environment only; no secrets, tokens, private H URLs, emails or
other personal data in code, fixtures, logs or evidence. Never invent results
or live footage. Demo/replay must be visibly synthetic; missing live keys/modules
must fail explicitly, never fall back to fake success.

## Acceptance and delivery
Use Python 3.12:
```sh
uv sync --frozen
uv run ruff check . && uv run pytest -q
```
Keep tests/test_journey_e2e.py and all CI green; CI never calls live providers.
Add normal, empty and error coverage for behavior changes. Where live behavior
is involved, verify it separately (at most three live runs per ticket), under
owner-approved read/prepare-only authorization plus applicable site review,
and record dated scrubbed observed evidence or an honest blocker in the PR.
No live run is required for docs-only work.

One branch from latest main, one PR named with this ticket's id/title, no direct
main pushes. Merge only in the declared order and after green CI, resolving
conflicts only within scope; squash-merge when authorized. Escalate scope or
interface gaps instead of editing unowned files. Each ticket writes its scoped
docs/handoff/<id>.md with changes, checks and pasted output, evidence, blockers
and next steps; parallel tickets do not update shared HANDOFF.md.
