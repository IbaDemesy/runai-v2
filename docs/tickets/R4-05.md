## Spec
Owner priority #1 (beautiful UX) and owner feedback (a)-(d) remain mandatory: ChatGPT-style suggestion pills under the latest assistant reply, chronological thread (new question below latest proposals), after launch only 3 agent cards + live screenshots with one friendly line (never raw task/prompt/JSON/logs), immediate typing/progress feedback with honest elapsed time.
Round-3 design issues to fix (UI rated 7/10):
1. Welcome headline missing space ('WE HANDLETHE REST' in EN; check FR too); html lang follows the conversation language.
2. FR conversations show 'RUNAI · YOUR COPILOT' / English pending copy before the first reply when the browser locale is EN: detect language from the user's typed text at send time (before the response) and use it for header/pending/typing copy.
3. Live stage: the LIVE/EN DIRECT badge only when the latest frame is < 15 s old; otherwise 'L'agent travaille · image il y a Ns' with a subtle animated shimmer/skeleton over the last frame (truthful, no fabricated frames); smooth crossfade; per-agent progress stepper with friendly stages derived from events (Démarrage -> Sur le site -> Sélection -> Prêt avant paiement / Bloqué), elapsed timer, site name/favicon text, and 'Essai d'un autre site' when hclient switches alternative (P7 step_progress).
4. Blocked copy must say WHY using reason_code + summary: sold_out ('Course complète'), no_inventory ('Plus de disponibilité à ces dates'), unreviewed_redirect, provider_error, session_failed, step_limit, captcha, login_required..., each with a concrete next step and the safe handoff URL button. Fix 'Durée 0s' on never-started agents (show 'Non démarré').
5. When all three agents are blocked before starting, replace three identical dead cards with one consolidated, friendly card explaining coverage and offering chips to change race/city/origin (send as normal guide messages).
6. Success state: when an agent is ready_for_payment show a celebratory but sober completion (checkmark motion, 'Prêt — à toi de payer sur <site>' CTA opening the handoff URL in a new tab, summary of dates/party/total if present in summary); 3/3 ready -> mission banner 'Tout est prêt avant paiement'.
7. Strava-grade data richness without inventing facts: race cards show distance (big numeric), date + countdown, city/country flag, official/registration source domain, and P9 preparation badges (Inscription ✓ / Complet / Non couverte, Hôtel ✓, Transport ✓) when RaceOption.preparation is present (hide when absent); plan card shows a route line origin -> city with dates, nights, party, budget tiles, and the 3 agents that will run with their target site when known. Elevation/field size/price only if present in data (never invented).
8. Overall polish: typography scale, spacing, orange #FC4C02 accent consistency, motion (reduced-motion respected), focus states, dark-on-light contrast AA, empty/loading/error states, 1440/1024/390 px without horizontal overflow, keyboard accessible chips.
Demo mode must exercise every state (add fake events in app.js test hooks only; never label demo as live). Evidence: docs/evidence/R4-05-ui.md with synthetic/demo screenshots only (no H-frame screenshots).

## Common rules
Branch from current main; one ticket, one branch, one PR. Only allowed files;
request a scope amendment otherwise. Read [round-3 findings](../eval/round-3.md)
if present. Import sibling interfaces lazily and fail closed when missing.

Never pay, book, create accounts, accept terms or consent, submit forms, enter
personal data or bypass captchas. Stop at the earliest boundary. Accor and
"prohibited" entries stay denied; unknown/expired reviews block before any H
session. Review actual terms first; prefer sites without captchas whose terms
allow agents and document choices. Live runs stop before payment.
H budget is not a constraint: run agents live in parallel whenever useful.

Write changes, pasted checks, dated scrubbed evidence, blockers and next steps
to `docs/handoff/R4-05.md`. Never publish secrets, private H URLs or personal
data; respect screenshot publication scope (H frames are in_session_only).
Synthetic footage is labelled and never proves live success.
