## Spec
Own the complete visual experience, not a cosmetic patch. Preserve the athletic Strava-inspired identity with an energetic orange accent, strong editorial typography, deliberate spacing, rounded clean cards, restrained motion and accessible contrast/focus. Review the round-1 desktop/mobile evidence and implement all four hands-on owner points.

Make same-origin live_frame screenshots PRIMARY and exclusive for the three browser surfaces. Never iframe, fetch/render or link to live_view_url/H trajectory JSON. A late share event/result must never hide a frame. Decode/preload a replacement image, swap only on success, maintain independent frame state per kind and show observed time plus live/stale/unavailable state. On frame eviction/404 or disconnect, keep the last valid image visibly marked stale or show an honest placeholder, not a fabricated animation. Keep following all three agents until each terminal state; terminal results must not replace their final screenshot. Replay preserves original timestamps and a persistent synthetic badge; demo has a persistent synthetic badge; hide the synthetic-only footnote in live.

After confirmation, transition to a spacious full-width agent stage: retain the three top-level agent cards/status/handoff controls and put live browser footage below their headers, with only a short human-friendly status line. Collapse the historical chat instead of cramping three browser surfaces beside it. No raw task, prompt, reasoning, JSON, tool names, technical logs or provider error dumps anywhere; map event types/result categories to curated status copy, not arbitrary e.message text. Three readable previews side by side at desktop, stacked without horizontal overflow at mobile; do not crop away the browser's relevant content. Avoid duplicate terminal summaries.

Render each conversational turn in this DOM/read order: assistant response, its latest candidate/selected-plan cards, then its single focused question, then elegant ChatGPT/OpenAI-style clickable suggestion pills/cards. Append later questions to their own latest turn; never append them beside the initial prompt or mutate previous proposals. Make candidate selection and suggestions obvious, keyboard-operable and comfortably tappable, with concise labels and metadata outside the button text. Only render a plan when a real/synthetic selected race exists. Format French/English dates and distances (e.g. 21.1 km, not 21.0975); show city/country, distance/date and safe official source badges from source_urls/retrieved_at without invented elevation/imagery/facts. Omit unavailable links instead of showing 'indisponible'. Display optional registration_access warnings from the pinned contract; unknown is not 'login-free'.

Immediately on send, show meaningful pending copy and candidate skeletons (under 250 ms, before awaiting fetch); use truthful elapsed-time/retry feedback, not fake source counts/progress percentages. Support the pinned background=true API and existing synchronous main responses, keep pending UI while polling discovering, handle timeout/empty/error/retry and generation changes without duplicating or losing turns/chips. Always require the explicit plan-confirm action; a suggestion never auto-launches. Prevent sensitive user text from appearing in local user-bubble echoes, error toasts or console output: redact card/contact/credential patterns before DOM insertion; backend sanitization is separate. No new frontend framework/CDN dependency.

Extend the existing Node DOM harness with behavioral assertions for chronological ordering, frame refresh even when share URLs arrive first/last, independent three-agent state, terminal last-frame retention, stale frames, mode changes, background and synchronous responses, sensitive echo redaction and retry. Replace tests that merely require an iframe with meaningful safety assertions. Record concise visual checks/evidence in the owned docs. Full post-integration live certification belongs to R2-05; this ticket must not claim that mock/demo footage proves it.
