# T08 — Live status and human handoff UI

## Goal
Deliver a beautiful modern dark/clean responsive design system: cohesive typography,
spacing, accessible contrast/focus, polished cards/buttons, subtle transitions with
reduced-motion support and smooth loading/empty/error/success states.
Use a guided chat with clickable suggestion chips and sourced race/plan cards,
not a long form that expects race dates. Integrate T02/T03 turns and T09's isolated
voice module, including app.py endpoint wiring and static stylesheet/script routes.
Show registration, hotel and train agents side by side on desktop, stacked on
mobile: each has live status, step log and real H live-view/share embed when
supported, or streamed screenshots plus a genuine public link. Handle blocked
embeds, missing/stale frames, provider errors and cancellation honestly.
Replay displays recorded frames/logs with original timestamps and replay/synthetic
labels. No fabricated sessions or footage; if frames are absent show unavailable.
T07 supplies adapter/replay plumbing. Document frame/event contracts. Keep no-build
static front unless a lightweight build is justified and extra scope approved.
Visually verify desktop/mobile chat, chip answer, plan confirmation, three live
agent panels, recorded replay and empty/error states; save screenshots and observed
interactions in HANDOFF.md. Offline pytest is not visual or live evidence.

## Acceptance
`uv run ruff check . && uv run pytest -q`

Full journey test must remain green in demo and replay. Add focused normal,
empty and error tests for new behavior. For live tickets the command is only
an offline regression check, NOT proof of a live run: attach dated observed
start/end URLs, stop state and scrubbed public evidence, with explicit approval.
No purchases, consent acceptance, account creation or submissions.
Update HANDOFF.md, then open one PR; merge only when CI is green.
