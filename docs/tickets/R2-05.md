## Spec
Own only core integration and current shared documentation; do not take over UI, guide, H client or builder modules.

Implement the pinned opt-in asynchronous discovery contract (CONTRACTS.md): `background=true` on create/messages returns 202 with a `discovering` Mission at once instead of waiting 40-51 s. Expose truthful, monotonic `discovery_progress` events through the existing GET polling, then append the resulting turn and move to guiding/ready. Keep the synchronous default (201/200), lazy provider loading, explicit missing-key/module 501 errors and bounded shutdown cancellation. Never fabricate source counts or progress. While discovering, return 409 for concurrent messages/confirmation instead of queueing them. Isolate failures, retries and stale results: a failed search can be retried and never leaves an orphaned mission. Timing/overlap tests use delayed stub providers and synchronization barriers, not live calls or long sleeps.

Redact user input before the guide, discovery, mission state or events can see it, and recursively sanitize public turn/result/event/error text as a second layer. Keep raw request input, exception/provider bodies and credential/contact data out of 422 errors, logs and snapshots, while keeping safe trip facts (dates, budgets, URLs). Reject confirmation of missing/stale/past/non-official live race dates or incomplete/inconsistent travel data, even when the guide says ready. Live never accepts synthetic races or results. Only an explicit `confirmed:true` on the current ready plan launches the three kinds, concurrently and exactly once, each with independent events/frames/results.

Remove the unconditional Accor/Omio fallbacks. Keep a genuine safe task/observed handoff, or null on blocked/failed. Never upgrade a result to ready or attach a success-looking fallback.

Docs: record the owner feedback, the adversarial-test requirement, the Accor/site-policy rule and the exact live-success definition in docs/feedback/owner.md. Refresh AGENTS/PLAN/HANDOFF/README/CONTRACTS and the queue. Publish these five tickets with their allowlists and pinned interfaces. Add a queue validator test.

Final acceptance: after R2-01..R2-04 are merged, rebase and run the full offline checks. Then run a UI-driven live acceptance of five cases (spring Italy marathon, Swiss summer trail, named Lisbon half, Berlin spring 10k in English, Spain February marathon), with the assistant proposing every date. Target at least two complete visible live successes in different countries, including one outside Milan. Report every safe blocker honestly in docs/eval/round-2.md.

## Acceptance
Commands: uv sync --frozen && uv run pytest -q tests/test_api_guided.py tests/test_units.py tests/test_journey_e2e.py tests/test_api_privacy.py tests/test_api_discovery_progress.py tests/test_r2_scope_contract.py && uv run ruff check . && uv run pytest -q. Integrated app: RUNAI_MODE=live uv run uvicorn runai.app:app --host 0.0.0.0 --port 8000 (keys from the environment, never logged).
Behavior: a paused discovery returns 202 with an id in under 1 s; progress is truthful and ordered; sync callers keep 201/200; provider failures can be retried; pending/past/unverified/synthetic/stale plans cannot be confirmed. Privacy tests plant sentinels and check captured guide inputs, stored state, serialized output, 422 errors and logs. Barrier tests prove all three runners overlap and duplicate confirms cannot launch more. The final report covers all five live cases and states plainly if acceptance is incomplete.
