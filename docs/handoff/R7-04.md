  default once the chosen eligible race has a known distance. Explicit race-type

  Editing temporarily clears readiness. Existing turn-bound chip IDs and the
  dedicated API confirmation boundary remain unchanged; guide turns never launch

- `GuideState` adds optional strict-boolean `profile_status` and the persisted
  `profile_invited` flag. `_turn` reads completeness defensively and invites the
  user once, with a continue-without-profile chip. Absent status is incomplete.

  the current `runai/app.py` / `runai/models.py`; therefore complete-status support
  is available on guide state, not newly wired into the mission API. Neither file
  was changed.

## Step 5 — PII context, live Linkup smoke and final verification

### Changes
- `step` now treats bare numeric dates as birth data only for 19xx years.
  Explicit birth contexts (`né/née le`, `born on`, `date of birth`,
  `date de naissance`, or birth labels followed by a numeric value) still refuse
  and redact the message, including 20xx dates. Ordinary words and race phrases
  such as `Born to Run` are no longer sufficient for a PII refusal.
- Day-first 20xx race dates are normalized to ISO before phone scrubbing and
  intent parsing, so `le 12/04/2027` / `on 12.04.2027` reach exact-date discovery
  rather than becoming a phone placeholder. Added normal/date/name-word and
  genuine birth/contact privacy regressions.
- The first smoke exposed generic empty-result copy for a missing named race.
  `_named_not_found` now also names the request when there are no alternatives,
  without pretending any alternatives were found. Added FR/EN empty-result tests
  and updated the allowed adversarial copy assertion.
- Named organizer searches without a user-specified year now query both current
  and next editions rather than implicitly restricting the search to next year.
  Explicit years remain unchanged. Added an offline provider-query regression.
  This corrected an overly narrow query observed in the initial Valencia path;
  the exact reason the provider returned empty results initially is unverified.
