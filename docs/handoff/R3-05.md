# R3-05 — runtime and core integration handoff

## Changes (2026-11-09)
- `hclient.py`: clause-aware unsafe-claim matching, URL/field/stop-boundary
  exclusions, affirmative FR/EN and explicit true-flag detection. Negation
  spans and/or, but never punctuation or but/however/mais boundaries. Trailing
  conditional boundaries are not execution claims. This intentionally changes
  the old ambiguous "No account created and booking completed" expectation;
  a separate affirmative clause still cancels.
- Terminal P4 codes distinguish policy, redirects, login/captcha, inventory,
  closed registration, budget/date mismatch, timeout, step limit, session,
  unsafe and provider failures. Raw provider/error prose stays private; existing
  human error strings remain. Prompts request immediate inventory/safety stops.
- Latest-image-only observation fetching, three-second polling/download bounds,
  transient image retries and SHA-256 frame deduplication. Resource validation,
  bearer isolation, screenshot size/MIME limits and no-share behavior remain.
- One fresh-session retry only before any observation, with old-session DELETE
  and the same overall deadline/policy decision. Steps cap at 80; wall clock
  defaults/caps at 600 seconds, with remote cancellation.
- `models.py`, `providers.py`, `app.py`: optional validated reason codes, unknown
  codes dropped to null, latest valid guide language copied to Mission; friendly
  builder-rejection summaries and no_site_coverage/policy_denied codes. Other
  provider exceptions have provider_error. Existing confirmation, concurrent
  launch, background discovery and privacy behavior retain offline coverage.
- `CONTRACTS.md` corrects the historical R2 step cap; `docs/evidence/h-client.md`
  records runtime boundaries. Fixtures and scrub.py needed no changes.
