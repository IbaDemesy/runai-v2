# R2-04 — robust guidance

## Step 1: schema and Linkup reliability

- `runai/guide/types.py`: strict-extra `RegistrationAccess`, optional on
  `RaceOption` with default None. Fields: nullable strict booleans
  `account_required` and `captcha`; nullable `source`, `observed_at` ISO date
  and `note`. These are EXACTLY the five pinned keys; step 1's status and
  evidence_url fields were removed in step 1b. Missing object means unknown,
  not open access.
- `runai/discovery/linkup.py`: scrubbed/instruction-filtered query, hints and
  source-derived display strings; JSON-delimited query data; public URL
  scrubbing; reject past-only editions rather than returning actionable past
  dates; prefer official future candidates without inventing dates.
- Step 1b: `discover(..., registration_info=None)` defaults to lazy optional
  `runai.agents.site_policy.registration_info(url)` lookup. An injected
  sync/async callable also receives only the registration URL (or official URL).
  Missing module/function, missing/invalid evidence and lookup failures stay
  None. Evidence requires a public source and non-future observation date;
  booleans remain strict and nullable. Observations are not authorization.
- `runai/discovery/__init__.py`: exports new errors, all subclasses of existing
  `DiscoveryError`: `DiscoveryTimeout`, `DiscoveryProviderError` (HTTP/network),
  `DiscoveryResponseError` (malformed/unsafe). `DiscoveryUnavailable` remains
  the missing-key error. Empty results remain `[]`; conflicting candidates keep
  `date_status=conflicting`, `race_date=None`. Existing call signatures remain
  compatible; 20-second default and configured 120-second app override retained.
- `tests/test_discovery_linkup.py`: offline normal/empty/conflict/provider-error,
  timeout preservation, injection, past-date, schema and access-evidence cases.
- `tests/test_guide_engine.py`: added new optional field to exact-schema
  contract fixture; step 2 adds behavior regression tests described below.
- `docs/evidence/discovery.md`: records offline-only revision and supersedes
  historical past-edition fallback. No new live evidence claimed.

## Step 2: bounded safe guide

- `parse.py`: scrubs text before parsing, bounded typo aliases (not fuzzy named
  race invention), deferrals, explicit language switches, mixed origin/stay
  details, invalid ranges, contradictory destinations/dates/years/seasons,
  unsupported tomorrow/past-date requests. Existing seasonal year rollover is
  retained, with sourced candidate dates displayed; no season is silently
  substituted on an empty search.
- `engine.py`: removes user-query echoes and question punctuation replacement;
  polite refocus with one question and chips. Initial conversation language is
  sticky until explicit switch. Deferrals select one eligible candidate with a
  sourced-future-date reason and editable suggested defaults; if none exists,
  explicitly propose/search a spring Italy marathon direction. New constraints
  in a deferral trigger a real discovery first. Empty/error results never invent
  a race. Known access blockers warn before selection; unknown is labelled.
- Scrubbing runs before history/query/hints storage, discovery and rendered
  turns; provider candidate strings are scrubbed too. Payment/account/terms/
  submission/captcha-bypass/rule-override requests receive explicit refusals,
  without storing/echoing their raw sensitive payloads.
- User travel preferences survive selection and relevant race changes; selected
  race/derived dates/readiness do not. Invalid budget/stay clears the invalid
  field and explains the range instead of clamping. Unsupported/contradictory
  event requirements invalidate the selection. Exact supported ISO event dates
  filter discovery results rather than substituting a different date.
- Only official, non-past event dates can be ready. Unknown, conflicting and
  unverified dates cannot produce `trip_payload`. Past provider results are
  rejected and offer a NEW discovery for next-edition evidence, not arithmetic
  date advancement.
- `fake.py`: injectable clock, future-relative explicitly synthetic fixture
  editions, explicit past fixtures filtered. Synthetic fixture date_status is
  official within the fake dataset, always paired with synthetic=True and
  synthetic labels/warnings; this is never live verification.
- The guide no longer sets stage=confirmed from text/chips. Ready plan chips
  merely keep the plan ready; app.py alone starts agents via explicit /confirm.
  Suggestion IDs are turn-scoped; invalid/stale IDs return unchanged state and
  current actionable chips. Updated old confirmation assertions accordingly.
- Offline tests cover these paths, missing registry module/function, empty and
  failing discovery, sensitive input, frozen dates, access warnings and stale
  actions. Full suite includes API-guided and journey E2E without editing them.

## Step 3: adversarial conversations

`tests/test_guide_adversarial.py` adds 53 table-driven artificial conversations
across all nine categories: off-topic, repeated dodges, mind changes,
nonexistent races, past dates, user/source injection and PII/payment requests,
typos/FR–EN mix, contradictory/impossible constraints, and premature/stale
confirmation. Every row checks the immediate response plus a normal follow-up
that recovers to an eligible ready plan without ever setting stage=confirmed.

The frozen-clock discovery double returns ordinary synthetic sourced candidates,
empty results or DiscoveryError, and can supply past/unverified/conflicting/
unknown dates or malicious source fields. Assertions inspect JSON-serialized
state, turns and captured query/hints for artificial card/email/phone/key/token
sentinels. They check one-question turns, sticky language, source/date provenance,
one evidence-backed recommendation, initial Lyon/2-night preservation, changed
race resets, new-edition re-sourcing and unchanged state on stale IDs.

Two reachable guide bugs were exposed and fixed:

- `parse.py` previously selected English whenever any English keyword appeared,
  so the required French-first typo/mixed-input example unexpectedly switched to
  English. Initial language now follows the first recognized language cue;
  explicit switching and sticky conversation language remain unchanged.
- `engine.py` scrubbed source PII but retained source instructions in candidate
  names, city fields and nested registration notes. It now recursively rejects
  such candidate rows before storing them. An all-unsafe result explicitly
  explains the rejection with `error=unsafe_source`, then permits safe recovery.

The new-year test intentionally accepts a NEW sourced edition with recomputed
dates after discovery rather than requiring a permanently empty selection:
auto-selecting a single newly sourced named-race option remains compatible with
the existing guide contract. It verifies a second discovery and a changed year.
