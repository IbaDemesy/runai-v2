# R1-03 — Linkup race discovery

## Changes

- Added `runai.discovery.discover` and safe `DiscoveryError` /
  `DiscoveryUnavailable` exports. Async structured Linkup search is read-only,
  accepts all scoped hints and supports an injected reusable httpx client.
- Normalize at most six candidates with exactly the requested public fields;
  stable Unicode-aware name/edition slugs, year-equivalent edition deduplication,
  future-first filtering and explicit unknown/unverified/conflicting dates.
- An official date needs a dated source on the identified official host or the
  exact officially linked registration URL. Registration links require a sourced
  organizer-page backlink. Missing/public-unsafe sources are discarded.
- Moved `httpx>=0.28,<1` to runtime dependencies and regenerated `uv.lock` without
  upgrading unrelated packages. Runtime-only imports work.
- Added 21 offline MockTransport tests; no CI test calls a live provider.
- Only the seven scoped files changed. No UI or integration files were touched;
  stale shared Milan-only instructions are outside this ticket's write scope.

## Limitations / integration next

- Use `await discover(query, hints, timeout_s=120)` for live integration: deep
  structured searches took 30.91–78.85 seconds here. All four first attempts with
  the specified 20-second default timed out. Do not hide this loading/error state.
- Standard search was faster but returned weaker and sometimes stale candidates,
  so the final implementation retains deep search. Three batches completed;
  no additional live verification was performed.
- `date_status=official` means Linkup extracted a date from an identified official
  source, not independent certification of every candidate. The assistant must
  resolve conflicting/unknown dates before plan confirmation.
- Past fallback is based on candidates returned by this search, not proof no
  future race edition exists. Query/fragment-bearing URLs are conservatively
  omitted to exclude potentially private/session links.
- The next integration ticket should feed these candidates into guided chat,
  present loading/error states and source links, then require explicit plan
  confirmation before any H run. No H-agent success is claimed by this ticket.
