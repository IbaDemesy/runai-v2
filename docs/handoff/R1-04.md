# R1-04 — Guided proposing conversation engine

Branch: `devin/r1-04-guide-engine`.

## Changes

- `runai/guide/__init__.py`: isolated package, no app integration.
- `types.py`: extra-forbidden Pydantic v2 race, suggestion, draft, turn and
  JSON-round-trippable state models; default factories for mutable fields.
- `parse.py`: deterministic accent-insensitive FR/EN parsing, European country
  and city aliases, distance, calendar-month hints (`YYYY-MM`), origin, nights,
  budget, travelers, correction and named-race intent. Today is injectable.
- `engine.py`: async injected discovery, validation/skipping invalid candidates,
  four-candidate limit, one focused question at a time, editable default chips,
  source/user/default provenance, date guardrails, scrubbed provider errors and
  retry, exact trip payload, explicit confirmation. No LLM/network/secrets.
  Natural bilingual acknowledgements, varied deterministic introductory prose,
  free-text corrections at every stage, small-talk redirection, yes/default
  acceptance, no/re-ask, and editable summary implement the additional owner ask.
- `fake.py`: visibly synthetic Italian marathons, Swiss trails, Lisbon half and
  unknown-date Chamonix ultra. Fixed fallback year 2027; month hints select years.
  All URLs use example.org; no live claims or personal information.
- `tests/test_guide_parse.py`, `tests/test_guide_engine.py`: normal, empty,
  invalid/error, FR/EN full conversations, five-turn acceptance, provenance,
  summary overrides, small talk, yes/no, date blocking, retry, JSON and payload.

## R1-03 contract assumption

Discovery is `async (query: str, hints: dict) -> list[dict]`. Each result uses
exactly these accepted RaceOption keys: `id`, `name`, `edition`, `distance_km`,
`city`, `country`, `race_date`, `date_status`, `official_url`, `registration_url`,
`source_urls`, `retrieved_at`, `synthetic`. `id`, `name`, `date_status` are required;
nullable metadata defaults to None, source_urls to [], synthetic to false.
date_status is official/unverified/conflicting/unknown. Dates and datetimes may
be ISO strings as accepted by Pydantic. Extra keys/invalid entries are skipped.
Country/city hints use canonical English names; distance is marathon/half/10k/
trail/ultra, months is a list of concrete YYYY-MM strings, named is boolean.
This interface is assumed, not verified against the parallel R1-03 implementation.

## Decisions, blockers and next

- No blockers. Only the eight allowed files are added; no shared contract,
  app, configuration, dependency or UI edits.
- Unverified dates may reach confirmation only with an explicit warning;
  unknown/conflicting/missing dates cannot. Fake dates are always synthetic.
- Nights are constrained to 1–14 and budgets/travelers positive; unsupported
  numeric answers leave existing values intact and conversationally re-ask.
- Parser is deterministic and bounded, not arbitrary-language understanding.
  Unsupported small talk stays on the current question without an error.
- No visual check: package is not wired into a rendered UI. User-facing copy
  is visually unverified. No live run was performed or authorized.
- Next ticket: wire this engine into app/UI and align discovery with R1-03;
  keep explicit confirmation and pre-payment/consent boundaries intact.
