# R4-01 PR-A — H runtime, core display boundary and Round 4 scope

## Changes

- `runai/agents/hclient.py`: P10 keeps start URLs under the existing reviewed
  navigation scope. Fallback URLs are handoff-only: public HTTPS, non-Accor,
  policy-approved and unexpired, without adding hosts to navigation permissions.
  Offline coverage builds the real Milan registration task.
- Raw about:blank, missing and empty observation URLs are ignored without
  frames, final URLs, progress or READY evidence. Before the first reviewed page,
  three blanks or 45 monotonic seconds block startup with provider_error and stop
  the session. Nonblank unreviewed redirects still block immediately.
- Observation polling waits at most two seconds; screenshot downloads have a
  three-second bound. The reviewed H docs provide no current-screenshot endpoint
  between steps: footage comes only from observation resources, never fabricated.
  Only the newest pending observation is fetched; older pending frames are
  superseded. Sequential fetching prevents stale frames from appearing last.
  Successful payloads are not re-fetched; transient failures may retry until
  superseded, with SHA-256 emission deduplication. Fake-clock cadence and ordering
  tests are synthetic evidence, not a guarantee of network delivery.
- Fixed French progress lines replace raw provider/task text and suppress
  consecutive repetition. P7 tries at most two supplied alternatives after the
  specified blocked reasons, checking each policy and sharing the original
  ten-minute maximum budget. Invalid alternatives are skipped. Results are never
  merged or upgraded: first READY, otherwise last attempted result.
- Failed/interrupted sessions after reviewed progress return blocked
  session_failed, the last reviewed public handoff URL and a friendly resume
  summary. Sessions stop before alternatives; pre-progress retry remains bounded.
- `runai/app.py`: P9 preparation survives turn serialization/privacy scrubbing
  for display but is recursively removed from mission trips and runner inputs,
  including state, trip_payload and draft fallback sources. FR/EN guide language
  copying is retained. Existing dictionary-based Mission turns need no model
  or provider changes. Tests cover normal, empty and malformed display metadata.
- `tests/test_hclient.py`, `tests/fixtures/h_vueling_observations.json`,
  `tests/test_api_guided.py`, `tests/test_api_privacy.py`, `tests/test_units.py`:
  offline runtime/core regressions; the Vueling fixture is explicitly synthetic.
- Shared planner edits included without rewriting: AGENTS.md, PLAN.md, README.md,
  HANDOFF.md, the R4-01..R4-05 queue/tickets, owner.md Round 4 feedback and
  CONTRACTS.md P7–P10. `tests/test_r4_scope_contract.py` replaces the deleted
  `tests/test_r3_scope_contract.py`. `docs/evidence/h-client.md` records the R4
  documentation findings and runtime boundaries.
