## PR review retry-controls follow-up

send() retains the previous chips and confirmation controls while awaiting and
rendering a response, removing only those captured controls after success.
Failure keeps them attached with their original callbacks, re-enables them in
finally and preserves the server error toast. A static regression check asserts
that removal occurs after rendering inside the success path, not before fetch.

## PR review security follow-up

Live preview embeds now require HTTP(S) and a different origin from the app,
resolved against location.href. Same-origin, relative same-origin and invalid
URLs cannot create an iframe or its open-tab link; they retain the frame or
unavailable fallback. Invalid replacement URLs clear an older iframe. A static
regression test asserts this guard and its use at the embed dispatch site.

## Contract alignment

Read PR #4 (`pr4`, 8807301) CONTRACTS, app, API tests and owner feedback.
The normalizer reads the last `Mission.turns` item, `draft`/`trip`, nested race
dates, `arrival_date` and `departure_date`. It also accepts direct turns,
`turn`/`mission` wrappers, `assistant_message`/`message`, `candidates`/`options`,
`plan`, `id`/`mission_id`, and `confirmation_required` for transitional responses.
Empty drafts do not produce empty plan cards. Unknown fields do not drive UI.

Both the plan button and `kind=confirm` chips POST `{confirmed:true}` to
`/confirm`; other chips send only `{suggestion_id}` to `/messages`. Confirm
controls only appear for ready turns. Free text sends `{text}` (plus mode on
create); English free text is not restricted, while interface copy is French.
One-click default acceptance is driven by the server's suggestion chips.

After 202, poll bare `/events?after=N` and the mission snapshot approximately
every second; deduplicate sequences/results and stop for completed/partial/failed.
Results provide final statuses/URLs, which step_finished events do not include.
Replay uses `recorded_at`, not current `observed_at`, as original time.
Health supplies initial mode and a visible missing-live-configuration hint.
No fallback live success, fabricated footage or hard-coded race/site selection.
Hotel/transport target URLs absent from the trip are explicitly unavailable in
the plan rather than invented; final genuine links come from runner results.
