## Evidence, decisions and blockers

No network calls, browser interactions or live H runs. Every external site-flow
claim is marked assumed. UI/site behavior is visually unverified. No inventory,
fare, checkout access or authorization is claimed. budget_eur is a positive
finite numeric total hint in EUR, not a computed agent allocation. Countries use
English names or ISO two-letter codes; unsupported origin inference uses flights.
Missing hotel budget requires human clarification before rate selection.

Use public search controls/result navigation read-only, preferring deep-linked
or public result pages. No form submission is allowed (including search,
guest/passenger details, login, account, booking, payment, consent or newsletter).
If results cannot be viewed without a forbidden step, report blocked.
Terms/cookie consent may only be dismissed, never accepted. Allowlisting does
not imply permission to automate. No outstanding coding blockers.

## Trip contract and read-only boundary alignment

Both builders now consume the unchanged core Trip mapping: race.city/country,
origin_city, travelers (integer >=1, default 1), optional budget_eur (positive
finite number, EUR), arrival_date and departure_date. Other race metadata and
nights are accepted but unused. Optional origin_country/hotel_preference remain.
Missing/invalid race/location/origin/dates fail with ValueError; departure must
be after arrival. Tests exercise the nested contract plus invalid party/budget.

Generic form submission is a stop boundary again. Public result navigation is
read-only with preference for deep-linked/public result pages; forbidden steps
produce a blocker, not an instruction to abandon viewable results.
Outbound fares must arrive on arrival_date before evening, departing on or
before it; return departs on departure_date. Tests assert these exact boundaries.
