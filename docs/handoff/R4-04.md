## Step 3 — concurrent discovery, transient retry and TTL snapshots

- `runai/discovery/linkup.py`: general and organizer-focused structured queries
  run concurrently with deterministic request-order merge. Each has a 15-second
  wall-clock budget, shortened by smaller caller timeouts. One retry on timeout,
  connection/transport errors and HTTP 429/5xx; no retry on other 4xx or malformed
  responses. The caller-owned client remains open. A successful query can retain
  its sourced results if its sibling fails, but partial failures are not cached.
- Added clearable, bounded 128-entry/30-minute in-process cache of nonempty,
  fully successful snapshots. Keys hash normalized scrubbed query/hints plus
  UTC date, never credentials; cache returns defensive copies. Monotonic clock
  can be monkeypatched for deterministic expiry tests.
- `tests/test_discovery_linkup.py`: 16 new offline cases covering overlap,
  deterministic merging, wall-clock timeout cancellation, transient retry,
  auth/no-retry cases, cache hit/expiry/clear/eviction and empty/error/partial
  non-caching. Existing fixture helper clears its artificial snapshots between
  changed fake inputs; broadened-search call-count assertion now counts two
  concurrent queries per discovery.
- `docs/evidence/discovery.md`: recorded offline evidence and limitations.
