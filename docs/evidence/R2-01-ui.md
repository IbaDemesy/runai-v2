## Changes checked offline

- Each appended turn reads response → latest sourced candidates/selected plan →
  one question → suggestions. Existing proposal text is not mutated; prior
  controls retire only after a successful response. No empty draft plan.
- Pending copy and skeleton cards are inserted synchronously before awaiting
  fetch; elapsed time is measured, not a simulated percentage/source count.
- Pinned JSON `background:true` handles 202/discovering with GET polling;
  older synchronous servers' additive-field 422 falls back without that field.
  Same-attempt retry reuses its turn and polls its mission before reposting.
- Post-confirmation stage expands to the page width and collapses chat.
  Screenshots alone form its three independent browser surfaces. The UI never
  reads, embeds, links, or fetches provider share/trajectory URLs.
- Replacement images preload and decode before swap; superseded loads and mode
  changes cannot overwrite another frame. 404/decode failures preserve the
  prior image marked stale; disconnect/retry is honest. Results and late share
  events never replace a final image. All three agents are followed to terminal.
- Replay timestamps come from recorded_at; synthetic labels persist. Live hides
  the synthetic-only footnote. Provider logs/prompts/errors are never rendered.
- French/English dates and one-decimal distances; city/country; source badges
  from safe source_urls/retrieved_at; optional account/captcha warnings. No
  invented elevation/images/facts, unavailable links or login-free assumptions.
- Local DOM echoes redact common card/contact/credential patterns. HTTPS public
  handoffs retain ordinary race/date/language queries but reject private
  booking/cart/order/contact/credential identifiers and all H URLs.
