# R3-03 — UI evidence

Date: 2026-11-08 UTC. **All race and browser footage here is synthetic demo
data. This is UI verification, not live provider or checkout acceptance.**

## Method

Started `RUNAI_MODE=demo uv run uvicorn runai.app:app --port 8000` and drove
Chrome through Playwright/CDP at `http://localhost:29229`. Completed the actual
welcome → proposals → default choices → ready plan → explicit confirm flow at
1440×900 and 390×844. At every captured state asserted
`document.documentElement.scrollWidth <= innerWidth`; exactly three agent
cards were present after confirmation. Also completed an English conversation
through the unmodified demo terminal response and checked English plan tiles,
confirmation CTA, agent headings, ready status and handoffs. No browser errors.

Demo finishes immediately. For the **running-stage screenshots only**, browser
route interception withheld terminal events/results, preserving the demo's
actual synthetic frame responses and step-start events. These images do not
prove a long-running agent session. The blocked screenshots are **explicit
visual fixtures** supplied through `window.__runai.event`, with `login_required`,
`no_inventory` and `no_site_coverage`. No real provider was blocked or contacted.
The retained variants keep actual demo illustrations; the no-frame variants
start from a fresh page to verify the designed terminal empty state.

Inspected every screenshot manually. The final design uses near-black/neutral
surfaces, orange primary controls, condensed system display type, race countdowns,
data tiles, orange hover/pulse states and framed synthetic illustrations. Follow-up
chips precede the final confirmation CTA. The mobile stage scrolls vertically;
only the first card fits in the initial viewport. Plan/confirmation images are
separate viewport positions in the same chronological thread, not stitched UI.

## Limits

- No real H/Linkup requests, private session links, personal data or secrets.
- Offline DOM tests cover all 16 reason codes in both languages, missing/unknown
  codes, old-but-running frames, events disconnect, snapshot-only failure,
  decode ordering, safe URLs, domain de-duplication and no raw event text.
- Reduced-motion overrides and contrast-conscious colors are implemented; this
  is not a formal WCAG audit or a cross-browser/device certification. The app
  deliberately keeps its dark surface colors under either OS color preference.
- Intermediate widths between the two requested viewports were not separately
  rendered. Real live provider screenshot cadence remains outside UI acceptance.
