# R6-05 · Design evidence

Date: 2026-11-09. Scope: frontend only. No live H runs or live evidence.
Demo/replay are synthetic; no H/site screenshots, private URLs or session ids
are committed. This ticket does not establish generic live success.

## Round-five critique → implementation

- Linux flag tofu: inline SVG flags for IT, FR, DE, NL, CH, ES, PT, BE;
  unknown supported ISO codes use a readable code chip, never flag emoji.
- Washed-out opening: warm orange starting panels, pulse and browser skeleton;
  queue copy stays explicit. Reduced motion disables animation.
- Stale EN DIRECT: live freshness uses the observation timestamp, not arrival;
  expires at 15 seconds even without a successful poll. Unknown/future times
  cannot claim live freshness. Terminal cards never show alternative activity.
- Verification end states: distinct checkpoint copy and safe site CTA without
  upgrading status; P4 reasons retain individual French/English recovery copy.
- Owner (a)/(b): accessible reply pills, descriptive metadata, independent turns
  and new questions below the latest proposals, never mutating earlier turns.
- Owner (c): three cards remain visible; only images, progress and friendly
  statuses; no provider tasks, JSON, technical logs or blocked host diagnostics.
- Owner (d): synchronous typing/skeleton insertion before the network request;
  staged discovery feedback with elapsed time, no invented result claims.
- Mobile: compact race card, two-column plan facts and sticky safe-area composer.
  The 390px route gives city names more room; Bruxelles stays whole. Tablet
  keeps three equal-width agent cards rather than stretching the third card.
- Queue glyph: a CSS clock replaces the system-font hourglass, which still
  rendered as tofu in Chrome after the country flags had been fixed.
- Typography/contrast: athletic scale retained; white small avatar text now uses
  the darker orange. Clear orange action/focus states, warm handoffs, 3/3 banner.

## Validation

Browser: existing Linux Chrome, Playwright 1.56.1 via CDP. Demo mode with a
visible synthetic label; no provider keys, external requests, or real H runs.
Initial matrix covered 29 named state variants per viewport, expanded to
37 captures with flag variants. Five additional lifecycle captures per width
covered freshness and terminal races. Final CSS-specific recheck on `a5e6b1d`
produced 11 fresh captures and 37 passing assertions per width.

| Measurement | 1440 × 900 | 1024 × 900 | 390 × 844 |
|---|---:|---:|---:|
| Initial matrix captures, reused for unchanged behavior | 37 | 37 | 37 |
| Fresh final-revision captures | 11 | 11 | 11 |
| Fresh final assertions | 37/37 | 37/37 | 37/37 |
| Typing first-paint opportunity | 19.8 ms | 12.2 ms | 21.4 ms |
| Separate three-dot screenshot completed within | 90.9 ms | 79.6 ms | 58.3 ms |
| Horizontal-overflow failures | 0 | 0 | 0 |

Typing was measured under controlled synthetic response delay in the local
browser, not as provider latency. The screenshot checks independently captured
the typing dots within the requested 300 ms.

Reviewed states include welcome, candidates, next question, suggestion pills,
edited plan, confirmation, opening, queued, running/changing frames, stale,
focus/Escape, alternative site, checkpoint FR/EN, absent-field fallback,
blocked, partial, 1/3, 3/3, discovery error, retry and empty recovery. Additional
flag variants cover all eight required SVG countries and a readable JP chip.

Confirmed behavior:
- Later questions follow the latest proposals/suggestions in DOM order;
  the actual Demo conversation reaches editable defaults and explicit confirm.
- All three agent cards stay visible through handoff. No raw task, prompt,
  diagnostic host, JSON sentinel or technical log is rendered in checked states.
- Synthetic freshness is available at 14,999 ms and expires at 15,000 ms without
  a new poll; terminal events clear timers and late frame decoding adds none.
- The 1024px running cards are approximately 303.36px each. Focus/Escape restores
  both the grid and keyboard focus at tablet/mobile sizes.
- Opening/queue dark-on-warm base contrast is approximately 17.15:1; reduced
  motion disables animation. Queued clocks are now CSS shapes, not font glyphs.
- No tofu observed in final reviewed screenshots, no browser page errors and
  no external requests in the scripted main matrix or final recheck.

Harness limitation: the original 450-assertion matrix reported three
case-sensitive `innerText` false negatives; focused canonical-text and final
editable-plan checks passed. Ordinary text scans also missed the hourglass
pseudo-element; the final review explicitly checked pseudo-content and pixels.
We do not report the initial matrix as an unqualified 450/450 pass.

Final offline checks: `uv sync --frozen`, `uv run ruff check .`, 1,940 full
pytest tests, 41 targeted static/journey tests and `node --check static/app.js`
all passed. Actual command output is in `../handoff/R6-05.md`.

The final primary Demo recording and current app-only screenshots were delivered
in the Devin session and selected screenshots are linked from the PR. No image
or video binary is committed. No live-provider correctness is inferred.

## Self-assessment

Subjective visual assessment after current screenshots: **8.5/10 for the
synthetic frontend at the required widths**, not an independent score or a
live-product readiness claim. The frontend-specific round-five flags, startup,
handoff-copy, chronology and responsive hierarchy concerns are addressed.

Residual polish: synthetic prefixes make mobile titles tall, the success-banner
decoration slightly crowds text, and origin correction has generic acknowledgement
copy. At the additional 320px width names remain bounded but Bruxelles splits;
390px meets the requested whole-name layout. Long/hyphenated origins remain
bounded at both widths. These limits prevent a higher assessment.

Integration boundary: `runai/app.py` on the current base drops the runner's
`observed_at`; models also need R6-01's additive P13 fields/codes. The UI cannot
recover a true H observation timestamp after it is replaced by emission time.
Both review findings were sent to R6-01, and the lead confirmed that ownership.
The frontend fails closed on missing/future timestamps, but honest live badge
behavior still requires that backend fix and live validation. This ticket does
not resolve all round-five product/integration critiques.
